How This Can Work With Lightspeed POS

This demo site is a redesign concept for The Hidden Reef. Here's how it could connect to the real Lightspeed-powered store — from simple redirects to a fully integrated storefront.

The current Hidden Reef website runs on Lightspeed eCom (Shop ID 648211), which is directly connected to their in-store POS system. That means product inventory, pricing, orders, and customer data all flow through Lightspeed already.

Any new storefront needs to work with that system — not replace it. Here are three ways to do that, from simplest to most integrated.

Option 1: Cart Redirect Easiest

How it works

When someone clicks "Add to Cart" on this demo site, it opens the matching product page on the real Hidden Reef website. The user finishes their purchase there like they normally would.

This demo site acts as a prettier front door — customers browse here, buy on the real site.

Pros

  • Zero backend work needed
  • No API keys or developer access required
  • Works today — could be set up in an hour
  • The real cart, checkout, and payments all stay untouched

Cons

  • No cart experience on the demo side
  • User leaves the demo to add items
  • Feels like two separate sites, not one

Option 2: Shared Cart via Lightspeed API Medium

How it works

The demo site connects to the Lightspeed eCom API behind the scenes. When a customer adds a product to their cart here, the demo sends that item to their real Lightspeed cart. When they click "Checkout," they're taken to the real Hidden Reef checkout — with their items already in the cart.

From the customer's perspective, it feels like one seamless experience: browse the pretty site, add items, and check out on the trusted real site.

Pros

  • Real cart experience on the demo site
  • Items land in the actual Lightspeed cart
  • Checkout, payments, and inventory stay accurate
  • Customers never see the old site until checkout

Cons

  • Requires a Lightspeed API key (from store admin)
  • Cart sync can occasionally lag if the API is slow

Option 3: Headless Commerce Most Integrated

How it works

The demo site becomes the actual storefront. It pulls real product data, pricing, and inventory directly from the Lightspeed API. The cart and checkout can either redirect to Lightspeed or be fully handled here. Lightspeed becomes the behind-the-scenes engine — the POS, inventory manager, and order processor — while this site is what customers actually see and use.

This is how many modern stores run: a custom-designed frontend on top of a proven commerce backend.

Pros

  • Full brand control — the site looks exactly how you want
  • Real-time pricing and inventory from POS
  • Fast, modern user experience
  • The old frontend can be fully retired

Cons

  • Payment handling is more complex if done on-site
What we're doing right now: The demo site uses Option 1-style cart redirects as a working proof of concept. "Add to Cart" links point to the real product pages on thehiddenreef.com. This shows the design and flow without needing any API access. When you're ready to go deeper, upgrading to Option 2 or 3 is a natural next step.

Getting Lightspeed API Access

To move from Option 1 to Option 2 or 3, you'll need an API key from the Lightspeed admin panel:

  • Log into Lightspeed eCom admin (the same dashboard used to manage the store)
  • Go to Settings → Apps
  • Find or create an API integration — this generates a client ID and secret
  • That credential pair lets the demo site talk to Lightspeed securely

The API provides access to products, categories, inventory, carts, orders, and customers — everything needed to build a connected storefront.

No rush. Option 1 works well enough to show the concept. API access can happen whenever the store owner is ready — the design and content work we're doing now doesn't depend on it.
