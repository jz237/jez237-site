Local changes from upstream:
- `examples/breakout/index.html`, `examples/td/index.html`: visible `#jz-version` tag (bump on every publish).
- `jez237/scores.ts`: shared high-score board — top 10 local (localStorage) + global (game-scores worker,
  boards `scenoco-breakout` and `tiny-bastion`), 3-letter initials via ▲/▼ or keyboard, takes all keys while open.
- Breakout `src/Progress.ts`: HIGH SCORES button on the splash; submits score + stage when a run is lost or won.
- Tiny Bastion `src/jzBoard.ts`, `src/Game.ts`, `src/MenuController.ts`: run score (enemy bounty ×10, 100×wave
  held, on a win lives×50 + stars×500×map), shown on the win/defeat panel and submitted with the map number;
  HIGH SCORES button under the map cards.

Rebuild (node 22+):

```bash
cd scripts/scenoco-three
npm ci --legacy-peer-deps --ignore-scripts
npm run build                                   # the @scenoco-three/* packages; examples import their dist
node build-jez237.mjs "$PWD" "$(git rev-parse --show-toplevel)"   # both games -> games/2026-10-31/, plus LICENSE.txt
```

`build-jez237.mjs` sets `assetsInlineLimit: 0`: jez237.com's CSP blocks fetch() of `data:` URIs, and
Vite would otherwise inline small models and sounds that way (Tiny Bastion then hangs on loading).

`npm run dev` inside an example still gives the live SceNoCo editor for modding.

## Millipede v3 (examples/millipede)

Jez's Millipede, rebuilt with Breakout's methods and look: a single `Main` scene, behaviours for the
rules (`Game`), the walking chains (`Swarm`, `Segment`), the mushroom field as four instanced batches
(`Field`), enemies (`Enemy.ts`), the gunner (`Player`), Breakout's bloom/tone-mapping (`main.ts`) and
camera rig, and the neon canvas textures. Audio is the classic edition's own mp3s and synth (`Sound`).

- `games/2026-04-28/millipede/` is an edition picker like Shatter Storm's (`index.html`, kept in the site repo):
  `neon/` is this example's build, `classic/` the untouched v2.2.0 game, and `audio/` the music and
  samples both editions load from `../audio/`. `classic/`, `audio/` and the picker are edited in place
  in the site repo; only `neon/` is generated. (`npm run dev` here has no audio: it lives one level up.)
- High scores: shared `jez237/scores.ts`, board `neon-myriapod` (the classic's global board), level = wave.
  The classic's local table (`millipede_scores_v1`) is copied into the new one on first run.
- Rebuild just this game: `node build-jez237.mjs "$PWD" "$(git rev-parse --show-toplevel)" millipede`.
  It empties `games/2026-04-28/millipede/neon/` first; everything in there comes from the example.
- Bump `VERSION` in `src/Game.ts`, the `#version` text in `index.html` and the picker's badge together on every publish.
