# Lancewing 2026 tools

Game: `games/2026-11-06/lancewing/` (three.js r181 vendored, plain ES modules, no build step).
Every local import carries the same `?v=N` (now `?v=16`, version 1.9.0 on the title). Since 1.4 the jousters are skinned (models.js `buildSkinned`): ~30 joints each (neck, jaw, frills, three-piece wings, legs, three-piece tail, helm, arms, cape, pennant) in one mesh per material class; perf_check 1.4: 33 programs throughout, S4/S5 waves 155/193 draw calls (were 304/339); since 1.4.1 an unhorsed skyray and its thrown knight fall as two pieces (render.js `fallBody`: the knight's joints move to a frame of their own), land on ledges / bounce off the rock instead of dropping through, settle flat and fade on see-through copies of their materials (`fadeGhost`, programs compiled in the warm-up); since 1.5 the lance and shield come off too (`throwParts`: four pieces, landing thuds / clanks through `R.sfx`), tips are a corner card that dims over riders / the boss (`placeTut`), the boss recoils and flinches on a hit (`bossKick`, a damped spring, render only; longer hit-stop on a weak point or phase), and dropping toward the sea reddens the screen, throws spray and beats a synthesized pulse (`seaDanger` in main.js, `A.pulse`); 1.6: dead skyrays go limp and thrown knights flail (`limpGhost`), wingtip vapour on fast flight (fireP), nearby riders' wing beats / landings are heard (`riderSounds`, audio `key:` gives them their own gap), and the sea warning adds a `#seamark` (▼ SEA) under the rider and a stronger glow; 1.7: frames are drawn BETWEEN sim steps (main.js `snapPrev` before every step, `lerpIn`/`lerpOut` around drawing, positions only; Replay `onStep` hook) - at 144 Hz 1.6 froze the drawn jouster on ~18 % of frames (scratchpad smoothprobe.mjs: 581 -> 48 stalls, unevenness 0.49 -> 0.10); the turn is a critically damped spring, pitch / bank come from smoothed velocities, a near-still jouster in the air hovers visibly (`V.hov`: faster deeper beats, nose up, stroke bob, legs down), and the camera follows with SmoothDamp; 1.8: the flying bosses (gale, wyvern, sovereign) cannot pass through ledges - sim `bossRam` cracks a ledge in the hull's path (look-ahead 0.6 s, at least 0.3 s warning, at once if already touching) and it shatters (`crumble` with `ram`), growing back after 6.5 s once its space is clear (`ledgeOccupied`); scratchpad bossprobe.mjs: time inside a ledge 19 / 17 / 29 % -> 2 / 0 / 2 %; in those sectors the static ledges also exist one by one, shown only in the boss wave (draw calls there 149 / 261 / 182); new SFX portal, arrive, screech, ram, regrow, thud, clatter, corefade (gen_audio.py sfx --only ..., process_audio.py without -I: it needs numpy); 1.9 (load): index.html modulepreloads every module (keep the list in step), `await R.warmUp()` compiles with compileAsync (KHR_parallel_shader_compile) and only the current sector's ledges / scenery / lighting map (`envForAsync`), the other sectors come from `R.prepareAll()` (idle after the title; a `?fixed` / `?test` page awaits it before its title, so the checks still count programs from boot), medium (phones) bakes textures at 512; live phone profile 7.0-7.4 s / one 5.4-5.8 s block -> ~4.3-5.2 s / 1.4 s, plus `js/main.js?v=` in index.html and `V` in js/audio.js.
The Node scripts load the game through `_game.mjs`, which reads the version from main.js, so they never need editing after a bump.

Difficulty lives in one table: `RAMP` in `js/config.js` (per sector `[first wave, last wave]`, interpolated per wave; `spoutW` / `boltW` = first wave index with that hazard;
`surv` = how long a survival wave lasts, `survCap` = riders added to `active` during it; `bossHP` / `bossRate` per sector). Every value only rises (or for warn / gap / react / coreT
only falls) from one wave to the next across the whole campaign (the self-test checks it). ENDLESS SKIES walks the same curve via `endlessLevel()` / `rampLevel()`.
Difficulty levels (`DIFFICULTY`, `applyDiff()`): easy / normal / hard / nightmare, score x0.6 / 1 / 1.5 / 2.2, warnings never below `MIN_WARN` (0.45 s). Each factor multiplies the RAMP value;
`k[sector]` says how strongly the level bites in that sector (factor m becomes 1 + (m - 1) * k), `kb` the same for the boss fights, `active` is applied as is, `lives` / `armor` are added.
Lives: 4 (`START_LIVES`), +1 per sector clear, +1 every 80 000 points (`SCORE.lifeEvery`, x the score factor); upgrades: salvage = sector score / 110 (`SALVAGE_DIV`), about one or two a sector.
