How AI Works

A chatbot does one thing: it predicts the next piece of text, over and over. A real language model — a very small one — is running inside this page. Give it a prompt and watch every step: text into tokens, tokens into numbers, numbers through layers, and one word chosen. Then wipe its memory and train it again yourself.

02Text becomes pieces

Tokens

A model never sees letters or words. A tokenizer chops text into pieces from a fixed vocabulary and hands the model a list of ID numbers. Most tokenizers are built by byte-pair encoding: start with single characters, then keep gluing together whichever pair shows up most often. Watch it happen to your prompt, or type anything.

    In a large model, the gap between two points carries meaning, so you can do arithmetic with words. Our model's world is too small to show that, so this map is a hand-built example space.

    Pick an example, or build your own from any three words. The arrows are drawn on the map above.

    Order has to be added by hand

    The table has one row per token and no idea where in the sentence that token sits. So a second learned row, one per position, is added on top. These are the first three tokens of your prompt.

    Key ideaTokens used in similar ways end up at nearby points — the model worked out that cats and dogs belong together purely from where they appear in sentences. And in larger models the gap between points is meaningful too: the step from man to king matches the step from woman to queen.
    The first map, the number strips, and the position rows are this model's actual weights; the map is a two-dimensional projection (principal components) of 24, so some real neighbours look further apart than they are. The colours are our labels, not something the model knows. The arithmetic map is hand-built so the sums come out exact; in real embeddings they are approximate. This model learns its position rows; other models use fixed wave patterns or rotate the vectors instead.
    04Tokens read each other

    Attention

    An embedding on its own knows nothing about its neighbours. Attention fixes that. At every layer, each token asks a question of all the tokens before it and pulls in information from the ones that answer best. It is the only place in the model where information moves from one position to another. These are the real weights for your prompt.

    Real model

    Every token's attention at once

    Each row is one token's question; each cell is how much it took from the token in that column. The hatched half is the future: a token can never look at what has not been written yet.

    The arithmetic, in slow motion

    What "asks a question" means in numbers. This is a hand-sized example with three numbers per vector, so every sum fits on screen; the model above does the same thing with twelve.

    Key ideaAttention is a weighted copy. Each token scores the earlier tokens for relevance, turns the scores into shares, and blends in that much of each one's information. A layer runs several of these "heads" side by side, each free to learn a different question.
    The arcs, percentages, and matrix are this model's real attention weights; nothing was arranged by hand, and no one told a head what to look for. If you retrain the model in chapter 7, the heads may divide the work differently. The slow-motion arithmetic is a constructed example, and real models also divide the scores by the square root of the vector size before the softmax.
    05The stack that does the work

    Layers

    One round of attention is not enough. A model repeats the same two-part block several times: attention gathers information, then a small neural network (the MLP) digests it. Each block adds its result to a running vector kept for every token — a shared scratchpad that grows more useful with every layer.

    Real model

    Start with one neuron

    The MLP is built from these. A neuron multiplies each input by a weight, adds them up, and passes the total through a curve that silences negative results. The weights are what training adjusts.

    Key ideaDepth is refinement. No single layer "knows the answer". Each one reads the scratchpad, adds a correction, and passes it up — and you can watch the guess go from an echo of the last word to a real prediction.
    The arcs and the per-depth guesses are computed from this model: the read-out decodes the last position's running vector at each depth with the model's own output layer, a technique called the logit lens. It is a peek, not something the model does when it runs. Sizes of today's largest models are mostly unpublished.
    06Scores, odds, dice

    Choosing the Next Token

    The stack ends with one score for every token in the vocabulary. A function called softmax turns the scores into probabilities. Then a sampler rolls weighted dice. The settings below change the dice — the model has already finished its work.

    Key ideaThe model does not look up an answer. It produces odds, and a sampler picks. Same prompt, different roll, different reply — which is why asking twice can give two answers.
    These are the real odds from this page's model () for your prompt, and temperature, top-k, and top-p are applied to them exactly as a production sampler applies them. A tiny model trained on a tiny world is often far more certain than a large one, so try a short prompt such as “the” to see a wide spread.
    07Where the numbers come from

    Training

    Every weight used in the chapters above began as a random number. Training shows the model real text with the next token hidden, measures how surprised it was by the truth (the loss), and nudges every weight a tiny step in the direction that would have made it less surprised. Then it does that again and again.

    08What a conversation really is

    A Chat Is One Long String

    Everything so far only continues text. So how does that become a conversation? A chat app glues the whole exchange into a single string, with special marker tokens saying who is speaking, and asks the model to continue it. When the model writes the end-of-turn marker, the app cuts it off and shows you the reply.

              11Guessing versus checking
              
    Tools and the Agent Loop
    
              
    On its own, a model can only produce text from its training and its context. Give it tools and wrap it in a loop, and it becomes an agent: it can ask for a file, a search, or a command, read the result, and decide what to do next. Watch who says what to whom.

    Key ideaAn agent is the same next-token predictor, run in a loop. A tool call is just text in a special format; the program around the model does the actual work and pastes the result back in. Every lap re-reads the whole, growing string.

The message pattern — request, call, result, call, result, answer — is how real agent systems work, and it is also the audit trail: you can judge the work from what was checked without seeing inside the model.
    
            
    
          
    
        
    

        
        
    
          
    
            
    
              12Different jobs, different machines
              
    Systems: Pick One, Build One
    
              
    "AI" is not one thing. The useful questions are where the model runs, where your text travels, and what is bolted on around it.
    
            
    
            Match the job
          
    
          
    
            
    
              
              
              
              
            
    
            
            
    
              
    Local model
    Runs on your own hardware. Private and offline; quality limited by the machine.
    
              
    Cloud model
    Runs in a data centre. Usually the strongest reasoning, at the cost of sending your text out.
    
              
    Agent
    A model plus tools, memory, permissions, and a loop. It can act — and so needs guardrails.
    
              
    Media model
    Turns prompts into pixels or sound. Needs visual direction, not just facts.
    
            
    
            
    Best fit: Cloud model. A gnarly bug benefits from the strongest reasoning available, and the largest models live in data centres. Your text makes a round trip; nothing acts on your machine.
