Astra was built on Windows using Python 3.12, Emscripten 3.1.46, Ninja, FFmpeg, NumPy, Pillow and UnityPy. The finished game has no build-time dependencies.

Place fresh checkouts at <build-dir>/redux and <build-dir>/physfs, at the revisions above. Set EMSDK to your activated Emscripten SDK. From this source folder run

    python prepare_engine.py <build-dir>
    python build_engine.py <build-dir>

build_engine.py keeps Emscripten cache, temporary files and object files in that build directory. A populated Emscripten library cache can be copied to <build-dir>/cache for an offline build. The compile produces engine.js with embedded WebAssembly in the parent folder.

The local asset pack can be rebuilt with a Python environment containing the dependencies above. D2 below is the original folder containing descent2.hog, and OL is Overload_Data.

    python package.py "<D2>"
    python materials.py "<OL>" "<D2>/groupa.pig"
    python cockpit.py "<D2>" "<OL>"
    python ship.py "<D2>"
    python ship_skin.py "<OL>"

engine.patch and the .inc files contain the platform and renderer changes relative to upstream. The port uses the unmodified upstream physics, AI and weapon simulation. The presentation shader in ship.frag is shared by the flight terminal and the in-game Pyro. material-index.json records the Unity texture names used in the local pack. Upstream engine notices are included in this directory.


Field Refit 02 also requires the original Vertigo install. Its mission archive and descriptor are copied without modification. In the same source directory, generate the extension packs with

    python vertigo.py "<original Vertigo files folder>"
    python fleet.py "<OL>" "<build-dir>/redux"
    python forge.py "<OL>"

fleet.py requires SciPy in addition to the dependencies listed above. The generated fleet_types.inc supplies D2 model bindings. The live D2 polymodel supplies each ship's outer panels and articulated limbs. Overload render batches supply internal mechanisms and materials. The original game handles the robot's position, weapons, collisions and AI. The optional encounter drop places the player near an existing robot; Enter mine uses the mission's original start.

The explosion renderer reads its density, surface normals and fuel from a 112 Ã— 112 Ã— 112 field. Rebuild the browser parcel using NumPy, SciPy and Pillow, from the game directory:

    python source/pyro_field.py pyro-field.js

The plume and blast includes implement optical sampling and particle motion. The engine patch contains their event lifetime, ship destruction timing, light propagation and sound triggers.

The ship explosion preview (preview.inc) uses the game's Pyro mesh, tier-2
blast renderer, and Descent II samples in a separate inspection camera. It
pauses the mission clock and input and creates no gameplay objects. Closing
it resumes the original pilot and camera. New variation chooses a new visual seed without advancing the gameplay RNG.
Replay same keeps that seed for frame-by-frame comparison.

Close hull impacts have shorter visual lifetimes and reduced radius/light
power. A view-distance fade reduces their optical density and sparks when a
living pilot is inside the cloud. Ship destruction keeps its full appearance.
The selected launch cockpit is also saved as the native preferred cockpit,
so the original respawn path restores the Astra flight deck.

Campaign coverage: Counterstrike contains 24 regular levels and six secret
levels; Vertigo contains 20 regular levels and three secret levels. Both use
the same engine, material packs, ship renderer, lighting, explosion system,
flight instruments and input code. No improvement is restricted to a level or
encounter shortcut. Level geometry, campaign progression, music selection,
AI, damage and flight physics continue to use the original game data/code.

Campaign validation: all 44 regular mines were loaded and rendered in the
shipping engine with the Astra deck. All nine original secret mines also
rendered with the same engine using a temporary test-only mission listing.
Explosion preview opened and resumed the final mine in each run. These were
loading/rendering checks, not complete gameplay playthroughs.

Astra collection and autonomous flight (pyre8)

All 45 defined powerup IDs now render as solid 3D models: energy, shields,
lives, keys, every weapon and missile pack, equipment, mines, hoard orb and

Rebuild the 51-entry mesh parcel (45 powerups, five reserved, one rescue pod):

    python source/collectibles.py collectibles.js

The inspection button uses the real native pickup renderer while the mission
is paused. It does not spend lives or ammunition.

The optional live demo uses a separate watch pilot and never persists that
pilot's game progress. A segment-graph planner respects keyed/locked doors,
seeks useful pickups, rescues hostages, shoots switches and attacks visible
robots/reactors. Aim, thrust, strafing, braking, projectile evasion and fire
feed the original control/weapon code. Enemy AI, flight physics and damage
remain unchanged. Death plays normally, then the demo retries automatically.
Briefings and score dialogs are bypassed only in autonomous mode. A completed
campaign loops back to its first mine. Next mine is also available to viewers.
The planner is heuristic; this is not a claim of a verified autonomous
playthrough of every puzzle, boss or secret-level route.

Phone viewing has a one-tap Watch live demo button, 960x540 default rendering,
large pause/resume, next-mine, sound and exit controls, and no pointer lock.
Backgrounding a phone pauses the demo. Unsupported fullscreen requests are
ignored safely. The browser still needs WebGL, WebAssembly and gzip streams.
Phone demos pace presentation to about 30 fps while retaining the completed
frame; the original manual-flight timing configuration is unchanged.

Validation: all 45 powerups and the rescue pod rendered in the native

An exit fixture verified native exit flight and automatic next-level loading;

Astra cockpit firing range and pickup decisions (pyre13)

Energy projectiles now derive their visual orientation from actual velocity.
Stock D2 does not maintain an orientation matrix for ordinary blob weapons;
using it made the enhanced shots and their trails point along the wrong axis.
This is a rendering correction, including for ricochets and enemy shots. Native
projectile motion, collisions, damage and flight physics are unchanged.
Luminous cores and soft additive glows replace the metal-looking geometry and
decorative hoops. Missile exhaust is drawn after the opaque body so the missile
does not paint over the exhaust that is closer to the viewer.

The weapon range now uses the cockpit view/zoom, the Pyro's actual gun mounts,
native projectile speeds and weapon fire intervals (Fusion/Omega use readable
showcase bursts). Paired cannons, alternating Spreadfire fans, rotating Helix
volleys, centered tracers, lightning and alternating missile tubes are shown
firing forward. The native weapon samples play. These are presentation shots in
a separate range; they never enter the mission or spend its ammunition. The
range controls collapse into a small button, including on phones.

The spectator pilot checks all secondary ammunition capacities, ammo-rack
capacity, ammunition remaining in dropped Vulcan/Gauss weapons, duplicate
equipment, laser upgrades, timed effects and lives before planning a pickup.
Uncollectible/reserved items have no default attraction. Native pickup rejection
starts a cooldown keyed to the object's signature. A failed approach also times
out, even when moving in a small orbit. Respawn forces a new plan after the demo
arsenal is restored; manual pickup behavior stays with the original game.

Validation: 85 capacity/drop cases compiled against native player/object types;
all 19 range entries, native pause-state snapshots, touch/desktop controls,
portrait/landscape layout, real combat and a full death/drop/respawn sequence.
The forced-death helper exists only in a separate local QA engine and is absent
from this release. Browser tests disable pointer capture and shut down afterward.

Robot armor darkens in stages with actual native health. Damage exposes glowing

Object signatures isolate damage histories across respawns and level changes.
Directional shield ripples and cockpit arrows use accepted damage and actual
collision points or explosion epicenters; invulnerability produces no false hit.
These presentation hooks do not change weapon damage, physics or demo decisions.

Optional Detailed (512) and Ultra (1024) receiver-plane shadow masks project
ship and machinery triangles from a same-room gantry fixture. Native door travel
drives a two-leaf shadow blocker and the shared hydraulic geometry. These are
bounded local wall shadows, not full-scene ray tracing. Basic remains available
for slower hardware and is the default on touch devices. Shadow quality is in
Settings and in the mine showroom's Controls. No new art parcels are required.

The effects showroom has quarter/half/normal/double speed, pause, a scrubbable
timeline, Replay same, and New variation. Weapon effects remain in cockpit view.
The damage/shield exhibit uses a detached robot and cosmetic shield events.
Preview clocks drive material animation as well as particles. Scrubbing is
silent, the mission clock remains stopped, and existing hit tints are restored
when returning to the mine. Native damage and pause-state tests cover both
campaigns; phone controls were checked in browser emulation.


Enemy archive and branching discharges (pyre29)

The showroom includes 25 original Overload enemy/boss forms, the Hologuide,
and four labeled archive prototypes. The pReactorA prefab contains no mesh
and is excluded. Enemy names and order were checked against EnemyType and
EnemyNamesType.Refresh in the installed Assembly-CSharp.dll. Dossier fields
come from desc_robots_EN; base armor and behavior flags come from robot_data.
Missing dossier information is marked as unrecorded rather than invented.

    python enemy_gallery.py "<OL>" "<output-game-folder>"

The extractor retains original proportions and authored 1024px material maps.
enemy-sources.json records coverage. Each model and its shared materials load
only when selected; neither the enemy catalog nor its assets block flight.
The WebGL1 gallery works independently of the native engine, including from
file URLs. Closing it releases its model buffers/textures and stops rendering.

Pickup corona paths use per-object deterministic visual hashes, midpoint
displacement, short restrikes, tapered forks, soft cores and discharge sparks.
Close pickups show up to nine independently timed discharges; distant pickups
use fewer paths. Arcs depth-test against the pickup and the mine, do not write
depth, and never consume simulation randomness or change pickup behavior.
The same renderer serves both original and Vertigo campaigns.
